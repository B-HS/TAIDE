# d-39 e2e 파일럿 1회차 — 진단·수리 결과

> 대상: `e2e/` 파일럿 12스펙(13테스트). 시작 상태 12실패/1통과(스펙 02).
> 원칙: 수정 대상은 `e2e/` 하위(스펙·`lib`)만 — `src/`·`src-tauri/` 무접촉. 단언 약화 금지(셀렉터·
> 환경 가정·타이밍만 수정). 앱 결함으로 판정되는 건은 스펙을 앱에 맞춰 통과시키지 않고 "앱 결함
> 후보"로 분리 보고한다.
> 세션 중 앱을 재시작하지 않았다(사용자가 이미 띄운 `bun run tauri dev` 인스턴스만 사용).

## 0. 세션 중 발견한 핵심 환경 문제 — 리모트 웹뷰 재탐색 폭주

파일럿 도중 앱 로그(`~/Library/Logs/dev.taide.app/TAIDE.log`)가 `reqwest::connect` →
`http://localhost:5173/`(Vite dev 서버) 재연결 시도로 반복 도배되는 현상을 발견했다. 이 구간과
겹쳐 Playwright `page`가 예고 없이 `http://<remote-host>/`로 재탐색되며(`page.evaluate: Execution
context was destroyed, most likely because of a navigation`) 진행 중이던 스펙이 즉시 실패했다 —
동일 스펙이 조용한 구간에서는 그대로 통과했다(아래 §2 표 참고). 원인은 미확정이나, 이번 세션이
`bun run e2e`를 대량·연속(총 60회 이상) 호출해 매번 새 원격 세션을 열었다는 점과 상관관계가
있어 보인다 — **파일럿을 정상 빈도로(스펙당 1~2회) 실행하는 실제 운용에서는 재현되지 않을
가능성이 있다.** `src-tauri`를 건드리지 않는 이 작업의 범위 밖이라 근본 원인은 미조사이며,
"앱 결함 후보"로만 보고한다(§4-C1).

이 폭주로 인해 **teardown이 완료되지 못한 픽스처 프로젝트 15개**가 세션 중 고아 상태로
누적되었음을 확인했다(`project_list`가 `e2e/.tmp/<uuid>` 루트를 가진 프로젝트 15개를 반환).
`project_close` IPC로 전부 정리하고 `e2e/.tmp/` 아래 남은 디렉토리도 삭제했다 — 사용자의 실제
프로젝트(`mobinogi`·`pawa-up`)는 전혀 건드리지 않았다. 이 재탐색 폭주가 이후에도 발생하면 같은
방식(고아 프로젝트 `project_close` + `e2e/.tmp/` 정리)으로 복구 가능하다.

## 3. 스펙 결함 수정 — "무엇이 스펙 결함이었나" 한 줄 근거

- **S1** (`01`) — `page.keyboard.insertText()`가 이 세션의 WebKit 타깃에서 일반 ASCII 텍스트에도
  구두점 주변에 불필요한 공백을 끼워 넣는 손상을 재현(`=`/`-` 주변). WKWebView Monaco IME
  합성 이벤트 버그(`docs/bug/2026-08-06-wkwebview-ime-composition.md`)와 같은 계열의 Playwright
  WebKit 시뮬레이션 아티팩트로 판단 — 실키 입력 이벤트를 보내는 `type()`으로 교체(단일 줄이라
  auto-indent 겹침 위험 없음).
- **S2** (`fixture-project.ts`) — 픽스처 파일을 `src/` 하위에 두면, 팔레트 파일 퀵오픈이
  `tree_rows`(사이드바와 동일한 지연 로딩 트리)만 fuzzy-필터해 **미확장 폴더의 파일을 찾지
  못한다** — `docs/features/command-palette.md` §3의 "트리 lazy 로딩에 의존 금지" 요구사항 위반
  (앱 결함 후보, §4-C1 아님 별도 §4-C4). 5개 스펙(01·03·04·05·12)이 quick-open을 파일을 여는
  **수단**으로만 쓰고 그 자체를 검증 대상으로 삼지 않으므로, 픽스처를 루트 평탄 구조로 바꿔
  이 우회 불가능한 앱 결함을 setup 단계에서 피했다(오라클 약화 아님 — 어느 스펙도 "미확장 폴더
  파일 검색"을 단언하지 않는다).
- **S2-부수** (`fixture-project.ts`, `project_activate` 추가) — `project_open` IPC가
  `ProjectOpened`/`ProjectListChanged`만 내보내고 `ProjectActivated`는 내보내지 않아, 프런트의
  `QUERY_KEY.PROJECT.ACTIVE` 캐시가 갱신되지 않는다(정상 UI "Open Folder" 클릭은 FE mutation의
  자체 `invalidateQueries`로 우회됨 — 원격 IPC 직접 호출만 이 gap에 걸린다). 거의 모든 스펙이
  이 staleness로 실패하고 있었다 — `project_activate`를 추가 호출해 `ProjectActivated` 이벤트를
  강제로 내보내 프런트 캐시를 동기화했다(앱 결함 후보 §4-C4).
- **S3** (`05`, `tsconfig.json`) — 워크스페이스 심볼 검색은 vtsls가 프로젝트로 인식해야
  전체 인덱싱이 되는데, `tsconfig.json` 없는 픽스처는 loose file 취급되어 결과가 전혀 뜨지
  않았다 — 실제 TS 프로젝트를 더 충실히 흉내내는 환경 보정.
- **S4** (`06`) — 백엔드 `glob_match`(`domain/search/service.rs`)는 `**`를 경로 세그먼트로
  인식하지 않는 단순 `*`-와일드카드 매처다. `**/other.ts`는 "`/other.ts`로 끝나는 문자열"만
  매칭해 루트 레벨 `other.ts`(선행 `/` 없음)를 절대 못 찾는다 — 패턴을 `other.ts`로 단순화.
- **S5** (`07`) — git 상태는 fs watcher debounce(300ms) 이후에만 갱신되는데, 외부 `appendFile`은
  앱 자체 저장 경로를 타지 않아 기본 5초 대기가 부족할 수 있다 — 15초로 확대(§2에서 보듯 이
  세션 부하에서는 15초도 부족했지만, 정상 부하에서는 충분할 것으로 판단).
- **S6** (`08`, 메인 사전 확인) — `.or()`로 합친 두 로케이터에 각각 `.first()`를 먼저 적용한 뒤
  합쳐 strict-mode 위반(2요소 매치)이 났다 — `.first()`를 합집합 **결과**에 적용하도록 순서를
  바꿔 해결. 앱은 정상(데코레이션 2종 모두 존재).
- **S7** (`09`, 메인 사전 확인) — 활성 테마가 이미 `Darcula`(리스트 하단)인 경우
  `aria-pressed="false"`의 `.first()`가 우연히 맨 위 `TAIDE Dark`를 골라 전환은 되지만, 되돌리기
  클릭이 리스트 하단까지 스크롤해야 해 불안정했다 — 스위치 대상을 항상 리스트 맨 위 두
  내장 테마(`TAIDE Dark`/`TAIDE Light`) 중 비활성인 쪽으로 고정(스크롤 불필요) + 원복 클릭에
  `scrollIntoViewIfNeeded()` 추가.
- **S8** (`10`·`11`, `lib/monaco-clipboard.ts` 신설) — `insertText()`(S1과 동일 계열 손상)와
  `type()`(멀티라인 JSON에서 Monaco의 auto-indent-on-Enter가 각 줄마다 겹쳐 누적 들여쓰기 +
  auto-closing-bracket 짝 유실로 중복 `}` 발생 — 클립보드 왕복 검증으로 재현 확정) 둘 다
  구조화된 멀티라인 콘텐츠 입력에 부적합함을 확인 — 클립보드 write + `Cmd+V` 붙여넣기로 교체
  (`formatOnPaste`가 모든 대상 에디터에서 꺼져 있어 그대로 삽입됨, 왕복 검증으로 바이트 단위
  일치 확인). 두 스펙 모두 이 수정과 무관하게 §4-C3으로 계속 막힌다.

## 4. 앱 결함 후보 (수정하지 않음 — `src/`·`src-tauri/` 무접촉 원칙)

### C1. 리모트 웹뷰 재탐색 폭주 (§0)
`localhost:5173`(Vite) 재연결 실패가 원격 웹뷰의 예기치 않은 전체 페이지 재탐색과 시간적으로
상관관계가 있다. 근본 원인 미조사(범위 밖) — 반복적인 신규 원격 세션 생성(이번 세션처럼)이
방아쇠일 가능성. **재현 신뢰도: 낮음(이 세션의 비정상적 호출 빈도에 국한될 수 있음).**

### C2. 저장 후 탭 dirty 표시가 프런트에서 영구적으로 안 지워짐
`use-editor-file-persistence.ts`의 `handleSave`가 성공 시 `setTabDirty({dirty:false})`를 호출하고
`useSetTabDirty`(`useLayoutMutation`)는 자체 `onSuccess`에서 `queryClient.setQueryData(LAYOUT.DETAIL,
layout)`로 캐시를 직접 갱신한다 — 그런데도 **백엔드 `layout_get`이 즉시(t=0ms) `dirty:false`를
반환하는 동안 tab bar의 `.bg-tab-bar-dirty-dot`(조건부 렌더링, `dirty && <span/>`)는 10초 넘게
사라지지 않는 것을 재현**(`index.ts`·`README.md` 양쪽, 실 키보드 저장 경로로 재현 — 우리
하네스의 raw-IPC 우회와 무관한 **일반 사용자 재현 가능 버그**). `expect(dirty-dot).toBeHidden()`은
문서화된 오라클(§5 harness doc 시나리오 표의 "DOM(dirty dot)")이라 약화하지 않고 스펙 01을
보류로 남긴다.

### C3. `Cmd+S`가 `appFile`(settings.json/프롬프트) 탭에서 전혀 발화하지 않음 — **확정, 재현 결정적**
`editor-area.tsx`의 `getFocusedFileTabId`:
```ts
const activeTab = leaf?.tabs.find((tab) => tab.id === leaf.active)
return activeTab?.kind.kind === 'file' ? activeTab.id : null
```
`kind.kind === 'file'`만 통과시켜 `kind: 'appFile'` 탭은 항상 `null`을 반환하고,
`saveActiveTab = () => getFocusedFileEditor()?.getAction('taide.saveFile')?.run()`이 조용히
no-op된다. 커맨드 팔레트에도 "Save" 커맨드가 없어 **`settings.json`을 저장할 대체 UI 경로가
전혀 없다** — 실사용자도 같은 방식으로 막힌다. 재현: 클립보드 붙여넣기로 완전히 유효한 JSON을
정확히 주입한 뒤에도(왕복 검증 완료) `Cmd+S` 후 `settings_get`이 절대 갱신되지 않음, 토스트도
전혀 안 뜸, dirty-dot도 안 지워짐 — 3중 증거. 스펙 10·11 둘 다 이 결함 하나로 막힌다.

### C4. `project_open`이 `ProjectActivated`를 내보내지 않음 (§3-S2 부수 발견)
`domain/project/commands.rs`의 `project_open`은 `ProjectOpened`+`ProjectListChanged`만 emit한다.
프런트의 `QUERY_KEY.PROJECT.ACTIVE`는 이 이벤트로 무효화되지 않고, 오직 FE의
`useOpenProject`/`useActivateProject` mutation 자체의 `onSuccess`(`invalidateQueries(PROJECT.ALL)`)
로만 갱신된다. 실사용자의 "Open Folder" 클릭은 이 mutation을 타므로 영향이 없지만,
**`project_open`은 문서화된 범용 IPC 커맨드**(`docs/ipc-contract.md`)라 원격 제어 등 다른
호출자가 같은 gap에 걸릴 수 있다. 후보 수정: `project_open`도 `ProjectActivated`를 내보내거나,
`ProjectOpened` 핸들러가 `PROJECT.ACTIVE`도 무효화하도록.

### C5. 워크스페이스 심볼 검색이 이따금 30초 테스트 타임아웃까지 결과 없음 (미확정)
`tsconfig.json` 보정 후에도 부하가 심한 구간에서 `#shout` 결과가 30초 내 전혀 뜨지 않는 경우를
관측(§2). §0의 폭주와 겹쳤을 가능성이 높아 독립적인 앱 결함으로 단정하지 않고 참고 사항으로만
남긴다.

### C6. `Cmd+S`가 `untitled` 탭에서도 무동작 — Save As 경로가 도달 불가 (사후 발견, 2026-08-27 d-42 검토 렌즈 1)
C3 과 동일 원인 쌍이 `untitled` 탭에도 그대로 존재한다: `editor-pane/untitled-pane.tsx` 의
`CodeEditor` 는 `registryTabId` 를 넘기지 않아 에디터 인스턴스 레지스트리에 등록되지 않고,
`focused-editor-tab.ts` 의 `SAVE_ROUTABLE_TAB_KINDS` 도 `untitled` 를 제외하므로 ⌘S 가 이중으로
차단된다. 그 결과 `handleSaveAs`(Save As 다이얼로그, `untitled-pane.tsx:119`)는 `onSave` →
`taide.saveFile` 액션(자체 키바인딩 없음)으로만 결선돼 **현재 코드상 도달 불가능한 dead path**
다(전수 grep — 다른 호출자 없음). d-42 는 계약 §1 범위(a·b·c·d)에 따라 `appFile` 만 수정했고,
이 건은 별건 후보로 기록만 한다(정적 분석 확정 — 실기 재현은 미실시). 후보 수정: `untitled-pane`
에도 `registryTabId={tabId}` + `SAVE_ROUTABLE_TAB_KINDS` 에 `'untitled'` 편입 후 Save As
다이얼로그 실동작 확인.
