# M8 HWP native engine 연결 전 근거

N5-P1g의 초기 읽기 전용 source/license/API 조사입니다. 후속 native 의존성·compile·기본 page/SVG/raster는 `2026-10-02-m8-native-hwp-preview.md`, 기본 approved worker/cache/File surface는 `2026-10-02-m8-native-hwp-host.md`에 기록했습니다. 전체 provider는 미완료입니다.

- 설치 `node_modules/@rhwp/core/package.json`·README·LICENSE와 `src/features/preview/hwp-preview.tsx`를 확인했습니다. 원본은 rhwp 0.8.2/MIT의 Rust/WASM `HwpDocument`로 pageCount/renderPageSvg를 호출하며 bytes 교체 후 page 0과 loading/error·render 실패 시 빈 화면을 유지합니다.
- [공식 v0.8.2 source](https://github.com/edwardkim/rhwp/tree/v0.8.2)를 조회하고 읽기 전용 `git ls-remote`에서 tag commit `9b16aa9e23f476e2b335d7c029fc9f24a199d63c`를 확인했습니다. 전용 sparse source checkout은 `/private/tmp/taide-rhwp-source.O6KKTB`이며 동일 HEAD를 확인했습니다. TAIDE checkout/branch와 사용자 bundle은 변경하지 않았습니다. 다음 세션에 임시 source가 없으면 같은 공개 commit에서 필요한 source만 다시 조회합니다.
- native 공개 API는 `DocumentCore::from_bytes(&[u8])`, `page_count()`, `render_page_svg_legacy_native(u32)`입니다. 원본 WASM wrapper도 같은 core를 사용합니다. Core에는 native Send compile-time assertion이 있으나 RefCell이 있어 Sync로 가정하지 않습니다. pure Rust native 경로가 있으므로 WASM/JS runtime이나 다른 outline 엔진으로 대체할 필요가 없습니다.
- native text 측정은 EmbeddedTextMeasurer이며 WASM은 Canvas callback+내장 metrics를 사용합니다. 동일 engine이라는 이유만으로 모든 글꼴/줄바꿈/픽셀 동등성을 통과로 계산하지 않습니다. upstream native SVG 기본 선택에는 RHWP_RENDER_PATH 환경 분기가 있으므로 앱은 확인된 legacy native 함수를 명시적으로 호출해 원본 기본 경계를 사용해야 합니다. from_bytes의 실험 환경 분기도 별도 검토 대상입니다.
- upstream CFB reader의 raw stream/read_doc_info/body `read_to_end`와 기본 `decompress_stream`에는 앱의 합산 상한이 없습니다. 별도 limited 함수가 있으나 일반 경로가 모두 사용하는 것은 아닙니다. HWPX는 entry XML 256MiB/BinData 512MiB 제한을 사용하므로 앱의 20MiB encoded·decoded/retained/cache 정책과 같다고 계산하지 않습니다. 기존 CFB FAT/DIFAT 정규화·ZIP/deflate read limit·aggregate/record/깊이/embedded OLE 경계를 parser 진입 전에 적용해야 합니다. 원본 file-external image 보충 API는 호출하지 않습니다.
- upstream manifest native PDF dependencies는 선택적 Skia와 별개로 포함돼 있습니다. root patch의 svg2pdf Git fork는 consumer에 자동 승계되지 않으며 registry svg2pdf 0.13.0으로 native compile을 확인했습니다. PDF export는 사용/검증하지 않았습니다. 정확한 revision/default-features·lock/feature·license/packaging 차이는 vendor `UPSTREAM.md`와 후속 QA에 기록했습니다. upstream toolchain은 1.93.1이고 app 1.95/root 1.89는 유지합니다.

HWP5/HWPX basic admission과 native 기본 page/SVG/raster·approved host/cache/File surface는 후속 QA에 기록했습니다. 표 metadata/u16 span과 ViewText extended header 오류도 수정·검증했습니다. 후속 배포용 bounded decrypt/decompress·기본 blank 렌더 결과는 `2026-10-02-m8-native-hwp-distribution.md`에 기록했습니다. 변경 없는 CFB/ZIP/record/XML/압축·참조 성공은 재사용합니다. HWP3/HML/전체 IR allocation/peak RSS·native strict/lenient·persistent engine 성능·전체 corpus/font/픽셀/OS/GPU/AX/CPU/cancel/crash gate는 남습니다. 다음은 HML 입력 경계입니다. N1~N8/Rust99%/제품 TS 제거/배포는 미완료입니다.
