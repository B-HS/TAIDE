# M7 격리 원격 인증·세션 단일 실측

## 범위

2026-09-29 계측용 release 앱 PID 44412와 합성 프로젝트에서 수행했습니다. 사용자 승인에 따라 이 격리 앱의 무암호 원격 서버를 일시적으로 켜고 일회용 접속 링크를 한 번 발급했습니다. 링크는 생성 직후 UI 화면 관찰에 표시됐지만 검사 명령·파일·문서에 값으로 기록하지 않았고, 사용 뒤 세션을 폐기했습니다. 세션 쿠키 값도 출력·저장하지 않았습니다. 접속 대상은 `127.0.0.1:49914`뿐입니다.

## 관찰

- 인증 없는 HTTP `/`와 WebSocket upgrade의 401, 잘못된 Host·Origin의 403은 [앞선 단일 실측](2026-09-29-m7-live-settings-memory-remote.md)에서 확인했습니다. 이번에는 그 성공 동작을 반복하지 않았습니다.
- 일회용 링크로 HTTP `/`에 접속한 응답은 200이었고 `Set-Cookie`에 `HttpOnly`와 `SameSite=Strict`가 있었습니다. 같은 쿠키를 보낸 별도 HTTP `/` 요청도 200이었습니다.
- 같은 쿠키로 `/__taide/ws`를 upgrade한 연결이 열렸습니다. `seq=1`, `command=remote_status` 요청의 응답은 `t=resp`, 같은 `seq`, `ok=true`였습니다. 앱 설정에는 연결 1개가 표시됐습니다.
- 앱의 `Sign Out All Devices` 조작 뒤 `All devices signed out` 알림을 확인했습니다. 이어 원격 스위치를 꺼서 `Stopped`를 확인했고, `lsof -nP -iTCP:49914 -sTCP:LISTEN`은 출력 없이 exit 1이었습니다.
- 검사기의 자체 30초 타이머가 먼저 동작한 뒤 WebSocket close code 1006이 관찰됐습니다. 따라서 연결 종료가 세션 폐기 때문이었다고 판정하지 않습니다. 7일 TTL의 실제 만료와 포화 시 실제 writer 종료도 이번 관찰에 포함되지 않습니다.

## 판정

실제 링크 교환, 보안 쿠키 왕복, 인증된 WebSocket의 대표 명령은 통과했습니다. UI의 세션 전체 폐기 조작과 서버 중지는 확인했지만, 기존 연결의 폐기 즉시 종료·TTL 만료·느린 수신자 큐 포화는 미완료입니다. 256프레임 상한의 기존 단위 검증은 [별도 QA](2026-09-29-m7-remote-ws-queue.md)에 기록돼 있습니다. 단일 대형 프레임의 바이트 메모리 상한은 사용자 결정에 따라 이번 범위에서 제외됐습니다.

이후 별도 연결의 [느린 수신자·활성 연결 폐기 단일 실측](2026-09-29-m7-remote-slow-receiver-revoke.md)에서 남았던 두 연결 수명 경계를 확인했습니다. 7일 TTL의 실제 만료는 여전히 미판정입니다.
