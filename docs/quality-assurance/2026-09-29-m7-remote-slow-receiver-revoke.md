# M7 격리 원격 느린 수신자·활성 연결 폐기 단일 실측

## 범위

2026-09-29 같은 계측용 release 앱 PID 44412의 합성 프로젝트에 별도 일회용 링크를 사용했습니다. 서버는 `127.0.0.1:50579`에 잠시 열었고, 테스트 뒤 모든 세션을 폐기하고 다시 껐습니다. 토큰과 쿠키의 값은 출력·저장하지 않았습니다.

## 관찰

- 같은 쿠키로 독립 WebSocket 두 개를 열었습니다. 제어 연결의 `remote_status` 응답은 `ok=true`였습니다.
- 느린 연결은 수신 소켓을 일시 정지한 상태에서 합성 1KB `small.txt`의 `file_read_raw` 요청을 6,000건으로 제한해 보냈습니다. 읽기 재개 전 수신 프레임 0개 상태에서 코드 1006으로 닫혔고, 독립 제어 연결은 계속 정상 응답했습니다. 256프레임 큐의 257번째 거부와 포화 신호는 이미 [단위 검사](2026-09-29-m7-remote-ws-queue.md)에서 확인했습니다. 실기에서 내부 큐 점유량이나 writer abort 로그를 직접 계측하지는 않았으므로 코드 1006 하나만으로 포화 원인을 단정하지 않습니다.
- 앱 원격 설정은 제어 WebSocket `1 connected`를 표시했습니다. `Sign Out All Devices`를 실행한 뒤 `All devices signed out` 알림, 제어 WebSocket의 코드 1006 종료, 앱의 `0 connected`를 순서대로 관찰했습니다. 이 검사기에는 자동 종료 타이머가 없었습니다.
- 원격 스위치를 다시 꺼 `Stopped`를 확인했습니다. `lsof -nP -iTCP:50579 -sTCP:LISTEN`은 출력 없이 exit 1이었습니다.

## 판정

실제 느린 수신자에서 유한 요청 후 연결이 종료됐고 다른 연결은 계속 서비스됐습니다. 기존 활성 연결의 일괄 폐기 종료도 확인했습니다. 코드 1006은 정상 close handshake 없이 끊긴 결과이며 클라이언트 단독 관찰만으로 내부 종료 분기의 정확한 이름은 확정할 수 없습니다. 7일 세션 TTL의 실제 만료와 한 프레임의 무제한 바이트 위험은 별도입니다.
