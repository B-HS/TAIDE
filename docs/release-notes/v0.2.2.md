## TAIDE v0.2.2 — TypeScript 오탐 밑줄 제거 · 파일 트리 전부 표시 · 언어 서버 진단 로그 (macOS Apple Silicon)

`node_modules` 가 멀쩡히 있는 프로젝트에서 TypeScript 파일의 모든 import 에 빨간 밑줄이 그어지던 문제를 고친 유지보수 릴리스입니다. 파일 트리가 `node_modules/`·`.next/` 같은 폴더를 숨기던 동작을 없앴고, 언어 서버가 왜 안 붙는지 로그로 알 수 있게 했습니다.

### 에디터 (TypeScript · JavaScript)

- `.ts`/`.js` 파일을 열면 `next`, `@/…` 같은 import 전부와 `process` 에 "모듈을 찾을 수 없음" 밑줄이 그어지던 문제를 고쳤습니다. 언어 서버(vtsls) 세션이 붙어 있지 않을 때 대신 도는 내장 TypeScript 검사기가 프로젝트의 `tsconfig.json` 도 `node_modules` 도 모르는 상태로 의미 검사를 하던 것이 원인입니다. 이제 언어 서버가 없을 때는 구문 오류만 표시하고, 완성·호버는 그대로 동작합니다.
- 언어 서버 세션이 붙어 있는 동안에는 내장 검사기의 진단을 완전히 끕니다. 같은 오류가 두 번 그어지거나 내장 검사기의 오탐이 서버 결과 위에 겹치지 않습니다.

### 파일 트리

- `node_modules/`, `.next/`, `.git/`, `target/`, `dist/` 등 지금까지 트리에서 통째로 숨겨지던 폴더가 다른 폴더와 똑같이 표시되고 펼쳐집니다.
- 검색·빠른 열기·파일 감시는 이전처럼 이 폴더들을 건너뜁니다. 그래서 `node_modules/` 를 펼쳐 둔 채 그 안의 파일이 바뀌면 트리가 바로 갱신되지 않을 수 있습니다. 필요하면 해당 폴더를 새로고침하세요.

### 언어 서버 진단 로그

- 앱 로그(`~/Library/Logs/net.gumyo.taide/TAIDE.log`)에 언어 서버 감지 결과(서버별 사용 가능 여부·실행 파일 경로), 시작(경로·인자·작업 폴더·pid), 종료(종료 코드·재시작 횟수·stderr 마지막 내용)가 기록됩니다. stderr 내용은 토큰·자격증명을 가린 뒤 한 줄로 남깁니다.
- 세션 시작에 실패하면 이전처럼 조용히 넘어가지 않고 경고를 남깁니다.
- 시작 시 PATH 보정이 성공했을 때도 항목 수를 기록합니다. 실패 경고는 이전과 같습니다.

### 알려진 제약

- 언어 서버 세션 중에도 내장 TypeScript 검사기의 완성·호버 제공자는 등록된 채 남아 있어, 완성 목록에 두 결과가 섞여 보일 수 있습니다. 진단(밑줄)은 끕니다. monaco-editor 0.56 이 이미 등록된 제공자를 되돌릴 수 있는 방법을 제공하지 않아 보류합니다.
- 언어 서버가 감지되지 않을 때 상태바나 편집기에서 그 사실을 알려 주는 표시는 아직 없습니다. 설정 → LSP 서버 화면과 앱 로그로 확인하세요.

### 설치

1. `TAIDE_0.2.2_aarch64.dmg` 를 내려받아 열고 TAIDE 를 Applications 로 드래그합니다.
2. Developer ID 서명·Apple 공증이 완료된 빌드라 별도 허용 절차 없이 바로 실행됩니다.
3. 무결성 확인(선택): `shasum -a 256 -c SHA256SUMS.txt`

요구 사항: macOS (Apple Silicon)
