# 에이전트·워크플로우 운용 — 정본

> AI 세션(Claude Code 등)에서 TAIDE 를 작업할 때의 역할 구조·위임·검증 파이프라인.
> 수 주에 걸친 세션들에서 정착·검증된 방식이며, 새 세션은 이 문서와 `docs/HANDOFF.md` 를
> 먼저 읽는다. 보편 컨벤션(`~/.claude/convention/*.md`) 위에 얹히는 프로젝트 고유 운용층이다.

## 1. 역할 5단

| 역할 | 모델·설정 | 책임 |
|------|-----------|------|
| 메인 | 세션 본체 | 오케스트레이팅·계약 작성·2차 검증·사용자 소통. **직접 구현 금지** — 예외는 ① 문서 정정 ② 실행이 막힌 인터랙티브 소수정(디버깅 계측 포함 — 계측은 반드시 원복) 뿐 |
| 리서치·조사 | opus + xhigh | 코드베이스 파악·근본 원인 분석·설계안 비교. 읽기 전용이어도 Workflow 로만(2026-09-04 지시) |
| 구현 fixer | opus + xhigh | 메인이 명확한 지시·구현 방법을 먼저 작성한 뒤 계약 범위 내 코드 구현. TS 는 병렬 허용, **Rust 는 한 시점 한 에이전트**(파일 경합 방지). (2026-09-04 이전: sonnet + xhigh) |
| 렌즈 검토 | sonnet + xhigh | 관점(렌즈)별 코드 검토 — 근본성·회귀·경계. 소형 배치는 1렌즈로 축소 가능하되 축소 근거를 기록. (2026-09-04 이전: opus + xhigh) |
| 적대적 검증 | sonnet + xhigh | 렌즈 major 발견 건별 반박 시도. **생략 가능 조건**: 다렌즈 수렴 / 실행 재현 / 기계(grep) 재현 + 메인 직접 확인 — 생략 시 근거를 계약에 기록 |
| e2e·테스트 작성 | fable + medium | e2e 스펙·단위 테스트 코드 생성 |
| 사용자 | - | 앱 실행·재시작(`tauri dev`/`build`) 전담, 실기 확증, 커밋·푸시·릴리스 지시, 결정 |

- 위임은 **Workflow 도구로만** 한다(Agent 단발 호출 금지 — 리서치·Explore 포함.
  `docs/feedback/2026-08-11-use-workflow-not-agent-tool.md` ·
  `docs/feedback/2026-09-04-research-must-use-workflow-opus-xhigh.md` 정본). 병렬성·재개(journal)·
  구조화 출력이 이유다. 독립 작업은 한 워크플로 안에서 `parallel`/`pipeline` 으로 병렬화한다.

## 2. 결함 처리 파이프라인 — 계약(d-##) 방식

결함·기능 배치 하나당 `docs/acknowledge/YYYY-MM-DD-d##-<slug>-contract.md` 1개가 정본이다.

1. **계약 신설** — §0 근본 원인(계측·소스 실물 증거), §1 수정 방향·범위 외, §2 실행·검토
   계획(렌즈 구성·적대적 여부), §3 기록(구현·검토·검증 결과 실시간 동기), §4 후속.
2. **구현 wf** — fixer 에 계약 경로를 전달. 구현 결과는 계약 §3 에 즉시 기록한다
   (기록 생략 재발 방지: `docs/feedback/2026-08-21-implementation-workflow-skips-contract-record.md`).
3. **렌즈 검토 wf** — 발견을 major/minor/info 로 분류. major 는 적대적 검증(§1 표의 생략
   조건 충족 시 생략+근거 기록).
4. **수용 반영 wf → 메인 2차 검증** — 아래 §3.
5. **사용자 실기** — 최종 오라클. 통과 후 커밋(§4).

- **기각·확정 항목 재론 금지**: 계약에 기각 사유가 기록된 항목은 이후 세션에서 다시 꺼내지
  않는다(예: HANDOFF §4 의 재론 금지 목록).

## 3. 에이전트 보고 불신 원칙

- 에이전트의 "완료·통과" 보고를 그대로 믿지 않는다. **메인이 실물 재검증**한다: 변경 파일
  직접 열람, 수치 재실측(grep·wc), `bun run verify` 직접 재실행.
- 검토·수정의 원문 JSON 은 태스크 출력 파일(`.../tasks/*.output`)에 보존하고 fixer 에는
  경로로 전달한다(요약 전달 시 정보 손실). 파일은 세션 소멸 가능 — **판정 요지는 계약 § 에
  실시간 반영**해 정본화한다.
- 워크플로 장애 시 `subagents/workflows/wf_*/journal.jsonl` 을 실사해 이어받는다
  (`resumeFromRunId` — 동일 프롬프트는 캐시 히트).

## 4. 커밋·푸시 규칙 (프로젝트 고유 우선순위)

- **대화 내 명시 지시가 auto-commit 합의(git config)보다 무조건 우선**한다. goal/요약 지시에
  커밋 포함 여부가 불명확하면 커밋만 보류하고 나머지 작업은 계속 달린다(멈추지 않는 것과
  커밋하지 않는 것은 양립). 정본: `docs/feedback/2026-08-27-commit-despite-no-commit-directive.md`.
- 분할 커밋: 논리 단위별(예: fix/feat/docs)로 **한 커밋분씩 선별 스테이징 → status/diff 확인
  → 커밋**을 반복한다. `git add -A`·stash(공유 워킹트리)·force push·AI 트레일러 금지.
- 병합·푸시: dev 에서 작업 → main 에 `--ff-only` 병합 → 양 브랜치 푸시가 관례.

## 5. 검증 문화

- **효율보다 완벽. 보류가 잘못된 수정보다 낫다.** 검토 축소 금지 — 렌즈 검토는 배치마다
  실결함을 적중해 왔다(d-43·d-44·d-46 major 등).
- 버그는 재현·계측 먼저(기법 목록: `docs/debugging.md` §4). 추측 수정 금지.
- e2e 단언 약화 금지 — 앱 결함은 앱 수정으로 해소한다.
- 종료 전 최소 기계 검증: typecheck → lint → test(+필요 시 `bunx vite build`). Rust 접촉 시
  `cargo fmt` 후행 필수.
- 실기로 확인 안 된 것을 "동작한다"고 단언하지 않는다 — 최종 오라클은 사용자 실기.

## 6. 세션 인수인계

- 단일 진입점 = `docs/HANDOFF.md`(스냅샷·문서 지도·재론 금지 목록). 작업 상태 = `docs/PROCESS.md`
  체크리스트. 결정·합의 = `docs/acknowledge/`. 교정 = `docs/feedback/`.
- 프로젝트 상태의 단일 출처는 항상 **실제 파일**이다 — 문서·기억과 어긋나면 파일을 신뢰하고
  어긋난 기록을 즉시 갱신한다.
- 확인 질문은 결정 지점을 모아 한 번에, 추천안 포함 번호 객관식으로. 보고는 표 선호.

## 7. 실행 경계 (에이전트가 하면 안 되는 것)

- 앱 실행·재시작(`tauri dev`/`tauri build`/`cargo run`)은 사용자만. `bun run e2e` 는 에이전트
  가능(비밀번호는 사용자 공급).
- `.env` 접근 금지·시크릿 값 기록 금지(이름만). HACK·검사기 끄기(`#[allow]`·`@ts-ignore`·
  `eslint-disable`) 금지 — 근본 해결만.
