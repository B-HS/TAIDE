### 0.3 이 저장소를 처음 보는 모델이 알아야 할 전제

- **언어 판**: native 크레이트는 `edition = "2024"`, `rust-version = "1.95"`입니다(예: `native/taide-native-app/Cargo.toml` 4~5행). Rust 2024 판에서는 `std::env::set_var`·`std::env::remove_var`가 `unsafe` 함수입니다. 검사에서 `HOME`·데이터 경로를 바꾸려면 환경변수를 바꾸지 말고 기존 코드처럼 주입 포트(예: `agent_cli::Ports`, `native/taide-native-app/src/agent-cli.rs` 34행)를 씁니다.
- **egui 0.36(즉시 모드)**: 매 프레임 `NativeApplication`의 UI 함수가 처음부터 다시 실행되어 화면을 그립니다. 위젯이 입력을 처리하는 코드와 그리는 코드가 같은 함수 안에 있습니다. 그래서 "render 안의 상태 변경"은 그리는 함수가 공유 상태(`EditorStore` 등)를 직접 바꾸는 것을 뜻합니다. 보조 창은 vendored eframe의 `show_viewport_immediate` 경로(`render_immediate_viewport`)로 그립니다.
- **panic**: 경계 없는 영역에서 panic이 나면 winit 0.30.13의 `stop_app_on_panic`이 앱을 멈추고, 다음 실행에서 hot-exit mirror와 세션 복원(shell-25)으로 복구합니다(`docs/quality-assurance/2026-10-27-native-error-isolation-file-drop.md` 65~76행 "shell-12 (구현하지 않음, 결정 필요)" 절). 경계는 `std::panic::catch_unwind(AssertUnwindSafe(..))`로 만듭니다(`native/taide-native-ui/src/error-boundary.rs` 183행). egui `Context`와 runtime `AppState`의 잠금은 `parking_lot`이라 poisoning이 없습니다. 잠금을 쥔 채 panic하면 반쯤 바뀐 상태가 감지되지 않고 다음 프레임에 그대로 쓰입니다(같은 절).
- **cargo 명령 형태**: `cargo <check|test|build> --manifest-path /Users/hyunseokbyun/development/TAIDE/native/<crate>/Cargo.toml --locked --offline --target-dir /Users/hyunseokbyun/development/TAIDE/experiments/native-shell-spike/target`. 한 번에 하나만 실행합니다. 앱 실행 파일이 둘이라 `cargo run`에는 `--bin taide-native-app`이 필요합니다(`docs/memory/2026-10-07-native-transition-operations.md` 6절).
- **앱 lib 검사의 선행 조건**: LSP 검사가 `native-lsp-mock` 예제 실행 파일을 씁니다. target을 비운 뒤에는 `cargo build --quiet --manifest-path /Users/hyunseokbyun/development/TAIDE/native/taide-native-app/Cargo.toml --example native-lsp-mock --locked --offline --target-dir /Users/hyunseokbyun/development/TAIDE/experiments/native-shell-spike/target`을 먼저 실행합니다. 없으면 `assertion failed: mock.is_file()`로 수십 건이 실패합니다(seams 문서 254행).
- **영역 구조**: 앱의 영역 코드는 `native/taide-native-app/src/domains/<영역>.rs`, 영역 host 요청은 `HostCommand::<영역>(Command)`, 영역 intent는 `ShellIntent::<영역>(intents::<영역>::Intent)`입니다. 공용 파일은 영역 블록 안에만 추가합니다(seams 문서 1.4절 표).
- **보호 번들**: `experiments/native-shell-spike/target/TAIDE M8 Egui Spike.app`과 `TAIDE M8 Iced Spike.app`은 사용자 실기용 번들이라 지우거나 덮어쓰지 않습니다(`docs/HANDOFF.md` 100행). 빌드 산출물 정리는 `cargo clean --profile dev`(`target/debug`만 지움)만 씁니다. `experiments/native-shell-spike/package-spike.sh`는 바로 이 번들 경로(`$SPIKE_ROOT/target/$SPIKE_DISPLAY_NAME.app`)에 복사·서명하므로 참고만 하고 실행하지 않습니다.
- **실기 격리 조건**: native 앱은 `--data-dir`로 데이터만 격리하고 홈 디렉터리는 실제 `HOME`을 씁니다. 그래서 GUI 실기에서 두 가지를 확인합니다. (1) IDE lockfile: `CLAUDE_CONFIG_DIR`이 없으면 `~/.claude/ide/<port>.lock`에 씁니다(`crates/taide-ide/src/lockfile.rs` 10·41~42행, `native/taide-native-app/src/ide-server.rs` 41행 `lockfile::lockfile_dir()`). (2) agent hooks: 설정 `agent_hooks_enabled`가 true이면 프로젝트를 열 때마다 `NativeProjects::new`가 넘긴 `agent_hooks::reconcile_installed`(`native/taide-native-app/src/projects.rs` 33행, `src/agent-hooks.rs` 106행)가 실제 홈의 agent hook 파일과 열린 프로젝트의 `.claude/settings.local.json`을 native hook 서버 주소로 다시 씁니다(`crates/taide-runtime/src/agent_hook_reconcile.rs` 79~100행, TAIDE 항목이 이미 있는 파일만). 기본값은 false입니다(`crates/taide-model/src/settings.rs` 544행). 새 격리 데이터 디렉터리는 기본값을 쓰므로 안전하지만, 실제 사용자 데이터 사본으로 실행하면(32-1) 이 값이 true일 수 있습니다.

### 0.4 세 배치 공통 규칙

1. 커밋·푸시는 메인 오케스트레이터만 합니다. 하위 작업자는 git 상태를 바꾸지 않습니다(`docs/memory/2026-10-28-native-lane-operations.md` 4절).
2. 작업자 금지 사항은 그대로입니다: GUI 실행, 사용자 데이터·OS 설정·클립보드·Keychain·휴지통, 합성 OS 입력, 저장소 밖 탐색, 허용 밖 의존성(같은 문서 60행). 이 중 게이트에 꼭 필요한 것은 `30-pending-permissions.md`의 해당 항목 허락을 받은 뒤 메인이 직접 하거나 사용자가 합니다.
3. 결과 기록: 게이트마다 `docs/quality-assurance/<날짜>-native-batch31-<주제>.md`(32·33도 같은 형식)를 쓰고, 실행한 명령과 실제 결과 수, 실패와 원인, 남은 것을 적습니다. `docs/PROCESS.md`의 W4 항목 아래에 체크리스트로 진행 상태를 남깁니다.

#### 절차

1. 각 행의 테스트가 쓰는 항목을 확인합니다: `rg -n "use |crate::|super::" <테스트 파일>`. UI 크레이트 안에서 컴파일되지 않는 앱 전용 의존(앱 `crate::` 경로)이 있으면 그 테스트는 앱에 남기고 공개 API로 바꿉니다.
2. 3. 앱 파일의 `#[cfg(test)] mod compatibility { include!(..) }`와 `cfg(not(test))` 분기를 지우고 `pub use taide_native_ui::<모듈>::*;` 한 줄만 남깁니다.

6. 검증: 옮기기 전에 앱 lib에서 해당 테스트 이름 목록과 통과 수를 기록합니다(`cargo test ... --lib -- --list`로 이름 목록, 필터 `keymap keybinding_editor keybinding_search tooltips problems_icons`). 옮긴 뒤 UI `cargo test --features native-host,inspection --lib`에서 같은 이름·같은 수가 통과하고, 앱 lib에서 사라졌는지 확인합니다. remote-web Wasm check를 함께 실행합니다(UI 크레이트를 바꿨으므로).

### 31-A5. native workspace 통합·CI 편입

#### 사실

- 루트 `Cargo.toml`의 workspace members는 `src-tauri`와 `crates/taide-*` 30개입니다. native 크레이트는 없습니다.
- CI(`.github/workflows/ci.yml`)는 `dev`·`main` push와 PR에서만 돕니다(5~8행). job은 `frontend`(bun typecheck·lint·format·test, ubuntu)와 `rust`(macos-latest, 루트 workspace의 `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, 49~76행)뿐입니다. native는 CI에 없습니다. `to_rust_native` push에서는 CI가 돌지 않습니다.
- 지금 native 전체 검사는 로컬 스크립트 `docs/utils/2026-11-03-native-merge-gate.sh`가 대신합니다.
- workspace마다 `[patch.crates-io]`가 다릅니다: 앱은 egui·vte, UI·remote-web은 egui, terminal은 vte. remote-web lockfile과 의존 그래프는 바뀌면 안 됩니다(동결).

#### 절차

1. 결정 필요: (A안) workspace는 그대로 두고 CI job이 크레이트별 manifest를 차례로 검사, (B안) `native/Cargo.toml` 하나로 app·ui·editor·syntax·terminal·retained를 묶고 remote-web은 제외. B안은 lockfile이 하나로 합쳐져 버전 선택이 바뀔 수 있으므로 P22 허락과 `cargo tree -d`(중복 버전 확인) 비교가 필요합니다. 추천은 lockfile을 바꾸지 않는 A안을 먼저 하는 것입니다.
2. A안 CI job 초안(새 job `native`, macos-latest): `dtolnay/rust-toolchain@stable`에 `components: rustfmt`와 `targets: wasm32-unknown-unknown`, `Swatinem/rust-cache@v2`의 `workspaces`에 native 경로들, 그리고 merge gate 스크립트와 같은 순서(LSP mock 빌드 → 앱 → UI → editor·syntax·terminal → remote-web Wasm check → fmt). 앱 테스트는 `-- --test-threads=4`를 유지합니다(운영 문서 2.3절 3번: host 큐 포화 흔들림 방지).
3. 트리거 브랜치에 `to_rust_native`를 넣을지 결정합니다(지금은 dev·main만).
4. 첫 CI 실행의 러너 시간·디스크를 기록하고 `timeout-minutes`를 정합니다. 앱 테스트 대상 한 벌이 로컬에서 약 25GB였으므로 러너 디스크가 부족하면 단계를 나눕니다.
5. native clippy는 지금까지 어떤 게이트에도 없었습니다. 처음 실행 결과를 기록하고 `-D warnings`를 붙일 시점을 결정합니다(기존 경고 목록: seams 문서 5.8절 8번).

완료 기준: native 검사가 PR CI에서 돌고 첫 실행이 성공(또는 알려진 실패만, 원인 기록)합니다.

### 31-B1. 전체 기능표 재감사

#### GPU fallback·device loss (2026-11-04 추가)

기능표에 행이 없지만 게이트 항목입니다: parity plan 3절 40행 "multi-window, sleep/wake, scale factor와 GPU device-loss fallback", 11절 140행 "release packaging, signing·notarization, GPU fallback 실기", 1절 14행 "자동화할 수 없는 … GPU·packaging은 대상 OS별 실기 gate". `docs/HANDOFF.md` 127행은 "다중 창, CJK IME 실기, 접근성, native 메뉴, 외부 파일 drop, GPU fallback 중 코드로 닫힌 것이 없습니다"라고 적었고, `docs/quality-assurance/2026-10-06-native-audit-architecture.md` 102행이 GPU fallback을 missing으로 판정했습니다. 이 가운데 다중 창(shell-4·6·7·8 complete, shell-5 partial), native 메뉴(shell-9 complete), 외부 파일 drop(shell-22 complete)은 이후 배치에서 구현됐지만 GPU fallback은 구현·검사 근거가 없습니다(`rg -n "wgpu_options|force_fallback|device_lost" /Users/hyunseokbyun/development/TAIDE/native --glob "*.rs" -g "!**/vendor/**"` 결과 0건).

사실(코드로 확인):

- 앱 `main.rs` 57~66행 `eframe::NativeOptions`는 `viewport`와 `window_builder`만 지정하고 나머지는 `..Default::default()`입니다. `wgpu_options`를 바꾸지 않습니다.
- 앱 `Cargo.toml` 56행 eframe feature는 `accesskit`, `default_fonts`, `wgpu`, `preserve_empty_paste_shortcuts`입니다. `glow`(OpenGL 렌더러)가 없어 다른 렌더러로 바꿀 길이 없습니다.
- egui-wgpu 0.36.2의 기본 `WgpuConfiguration::on_surface_status`(cargo registry `egui-wgpu-0.36.2/src/lib.rs` `impl Default for WgpuConfiguration`)는 `Outdated`면 `Reconfigure`, `Lost`면 `RecreateSurface`, `Occluded`면 `SkipFrame`입니다. 즉 표면(surface) 손실은 기본으로 다시 만듭니다.
- device 손실 처리: egui-wgpu 0.36.2 소스와 vendored eframe(`experiments/native-shell-spike/vendor/eframe/src`)에서 `device_lost`·`set_device_lost_callback` 검색 결과가 0건입니다. wgpu 30.0.1에는 `Device::set_device_lost_callback`(registry `wgpu-30.0.1/src/api/device.rs` 681행)이 있습니다. 기본 adapter 요청은 `force_fallback_adapter: false`(egui-wgpu `src/lib.rs` 155행)입니다.

절차:

1. 결정 필요(사용자에게 묻기): (A안, 추천: 근거 없는 구현을 늘리지 않음) 먼저 실기로 현재 동작을 기록하고, device 손실은 wgpu `set_device_lost_callback`으로 감지해 hot-exit flush 뒤 오류 안내·재시작으로 처리하는 설계를 별도로 올림 / (B안) eframe `glow` feature를 추가해 wgpu 실패 때 OpenGL로 시작(앱 `Cargo.toml`·`Cargo.lock` 변경, P22) / (C안) macOS Apple Silicon만 출시 대상이므로 GPU fallback을 범위 밖으로 정하고 위험을 기록.
2. 실기(P23, 사용자 조작): 외장 모니터 연결·분리, 창을 다른 배율 모니터로 이동, 잠자기·깨우기, 전체 화면 전환 뒤 화면이 다시 그려지는지와 입력이 되는지 확인하고 stderr 로그(`stderr_log::install`, `main.rs` 18행)를 기록합니다. native stderr 로거는 Warn 이상만 출력하므로(`native/taide-native-app/src/stderr-log.rs` 3·36행) egui-wgpu 기본 처리의 `Outdated`(trace)·`Lost`(debug)·`Occluded`(trace) 기록은 보이지 않고, 그 밖의 표면 상태만 `Dropped frame with error` 경고로 나옵니다. 화면이 멈췄는데 로그가 없으면 이 수준 차이 때문일 수 있다고 함께 적습니다.
3. A안을 고르면 device 손실을 검사로 재현하는 방법(wgpu에 손실을 강제로 일으키는 공개 API가 있는지)을 공식 문서와 registry 소스로 먼저 확인합니다. 확인 전에 구현하지 않습니다.

완료 기준: 표의 모든 항목이 "통과 / 차이(의도·근거) / 결함(행 판정 낮춤)" 중 하나로 기록됩니다. GPU 소절은 결정된 안의 근거(실기 기록 또는 범위 밖 결정)가 있습니다. 허락이 없어 못 한 항목은 "대기"로 두고 완료로 올리지 않습니다(배치 계획 27행).

### 32-1. 기본 데이터 경로·keychain 승계(shell-15)

사실:

- shell-15 행(기능표 108행): "현재 launch는 절대 격리 --data-dir를 요구하고 별도 secret namespace를 씁니다. 기존 사용자 데이터/자격 증명·실제 제품 경로 전환/롤백은 남아 있습니다." 판정 partial.
- native 실행: `LaunchConfig::parse_data_dir`(`native/taide-native-app/src/bootstrap.rs` 51~72행)가 첫 인자가 `--data-dir`가 아니면 `"native app requires --data-dir <absolute isolated directory>"`로 거부합니다. 경로는 절대 경로·루트 아님·`..` 없음이어야 합니다. secret 서비스는 15행 `net.gumyo.taide.native-isolated`입니다.
- Tauri 앱: 데이터는 `app.path().app_data_dir()`(`src-tauri/src/lib.rs` 914행), keyring 서비스는 identifier(929행 `SecretStoreState::new(app.config().identifier.clone())`), identifier는 `net.gumyo.taide`(`src-tauri/tauri.conf.json` 5행). identifier 변경 문서에 따르면 macOS 데이터 경로는 `~/Library/Application Support/net.gumyo.taide`입니다(`docs/acknowledge/2026-08-29-bundle-identifier-rename.md` "절차" 2번).
- keyring 계정 이름: `ai-ollama-cloud`, `ai-codex`, `ai-omlx`, `github-sync`, `remote-access`(`crates/taide-infra/src/secret.rs` 10~28행 `SecretAccount`). 이전 identifier 변경 때 "키체인은 이관 불가(시크릿 비접촉 원칙) — 재입력 필요"로 처리한 선례가 있습니다(같은 문서 3번).
- 로그: Tauri는 `tauri_plugin_log::Builder::new()`(`src-tauri/src/lib.rs` 834행)로 로그 플러그인을 쓰고, native는 stderr 로거만 있습니다(`stderr_log::install`, `main.rs` 18행). shell 사양 4.1 결정 3: "파일 로그(원본 로그 폴더)는 실제 사용자 경로라 shell-15와 함께 다룹니다".

결정 필요(한 번에 묻기):

1. native 기본 데이터 경로: Tauri와 같은 `~/Library/Application Support/net.gumyo.taide`(추천 후보: 기존 데이터를 그대로 승계, 계약 3.1절과 일치) / native 전용 새 경로(첫 실행 때 복사 이관).
2. keychain 서비스명: Tauri와 같은 `net.gumyo.taide`(기존 토큰 재사용) / 격리 유지 후 사용자가 재입력. 같은 서비스명을 쓰면 다른 서명의 실행 파일이 기존 항목을 읽을 때 macOS가 접근 허용을 묻는지 실기로 확인해야 합니다.
3. `--data-dir`를 검사·개발용 선택 인자로 남길지.
4. 파일 로그 위치와 형식.
5. 같은 데이터 디렉터리를 Tauri 앱과 native 앱이 동시에 열지 못하게 할 방법. Tauri는 `tauri_plugin_single_instance`(`src-tauri/src/lib.rs` 821행), native는 데이터 경로 해시 기반 Unix 소켓(`native/taide-native-app/src/single-instance.rs` 32~37행 `socket_path`)이라 서로를 모릅니다(두 앱을 함께 실행하면 같은 파일을 동시에 쓸 수 있는지 확인 필요).

절차(결정 뒤):

1. 실패 검사 먼저: `Launch::parse`가 `--data-dir` 없이 기본 경로를 고르는 경우, 잘못된 경로·권한 오류, 기존 Tauri 데이터 디렉터리 읽기, future schema 거부를 주입 경로(임시 디렉터리를 기본 경로 공급자로 주입)로 검사합니다. 환경변수를 바꾸는 검사는 쓰지 않습니다(Rust 2024의 `set_var`는 `unsafe`).
2. `bootstrap.rs`의 경로 선택과 `SECRET_SERVICE`를 결정대로 바꾸고, 결정 5의 동시 실행 방지를 구현합니다.
3. 실제 데이터 실기(P05 허락 뒤): (a) 사용자가 Tauri 앱을 종료, (b) `~/Library/Application Support/net.gumyo.taide`를 백업 위치로 복사(사용자 확인 뒤), (c) 실행 전에 그 데이터의 `settings.json`에서 `agentHooksEnabled` 값을 읽어 사용자에게 알림. true이면 native가 프로젝트를 열 때 실제 홈의 agent hook 파일과 각 프로젝트 `.claude/settings.local.json`을 native hook 서버 주소로 다시 쓰고(0.3절 "실기 격리 조건" (2)), Tauri로 돌아가면 Tauri가 같은 reconcile로 다시 자기 주소를 씁니다(`src-tauri/src/lib.rs` 1038행 부팅 시, `src-tauri/src/domain/agent/capability.rs` 22행 프로젝트 capability 연결 시). 이 왕복을 허락할지(P07) 함께 묻습니다. (d) `CLAUDE_CONFIG_DIR`을 실제 값으로 둘지(실제 IDE 연동 확인, P08) 임시 값으로 둘지 정하고 native 실행으로 프로젝트·탭·설정·hot-exit 초안·테마·언어팩·snippet·plugin·LSP 경로를 확인, (e) 종료 뒤 Tauri `v0.3.0` 실행으로 같은 데이터 확인, (f) 결과를 QA 문서에 기록.

완료 기준: shell-15 complete(구현·실제 경로·자동 검사), 실제 데이터 왕복 기록, rollback 절차 문서(32-3).

### 32-2. 단일 인스턴스·CLI 연결

사실:

- CLI(`crates/taide-cli/src/main.rs`)는 `TAIDE_APP_PATH`(15행), 없으면 `/Applications/TAIDE.app/Contents/MacOS/TAIDE`(16행), 없으면 개발 경로 `target/debug/taide`(17행)를 찾아 `<파일들> [--wait-marker <marker>]`로 실행합니다(`spawn_app` 119~135행). `--data-dir`를 넘기지 않습니다.

절차:

1. 32-1에서 `--data-dir` 없는 실행이 생기면 CLI가 넘기는 인자 형식(`<파일들> [--wait-marker m]`)을 native가 그대로 받는지 자동 검사합니다(`Launch::parse` 단위 검사, 기존 `single-instance-tests.rs`의 중계 검사 확장).
2. 번들 실행 파일 이름과 CLI 상수(31-B6 결정 a)를 맞춥니다.
3. 실기(P06 허락 뒤): 서명된 native 번들을 `/Applications/TAIDE.app`에 설치(기존 Tauri 앱을 대체하므로 P25 범위), `/usr/local/bin/taide` 설치(P03), `taide <파일>`, `taide --wait <파일>`(탭 닫힘 때 CLI 반환), 앱 실행 중 두 번째 실행의 중계, Claude Code Ctrl+G 외부 편집을 확인합니다.

완료 기준: 실제 CLI → native 열기와 `--wait` 해제 실기 기록, 전환 계약 4절 4번("CLI `taide --wait` … 동등") 충족.
