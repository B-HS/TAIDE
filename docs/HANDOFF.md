3. 동일 코드·입력·환경의 성공 검사는 재사용합니다. 반복 계측·전체 검사 고정 실행·앱을 매 기능마다 켰다 끄기를 하지 않습니다. 변경 위험을 직접 덮는 검사만 한 번 실행하고 실패 영향 수정 뒤 관련 검사만 한 번 재실행합니다.

5. M8 전체 게이트 통과 전 기존 TS/React/Tauri/Monaco/xterm UI·제품 데이터를 제거하지 않습니다. 최종 전체 완료 후에만 관련 변경을 선별 commit·일반 push합니다. force push·git add -A·AI 서명과 무관한 정리는 금지합니다. 인계/pause 동안 Git 변경을 하지 않았으며 재개 후에도 전체 M8 미완료로 commit·push하지 않았습니다.

## 중단 지점: 탐색기 삭제와 LSP 삭제를 혼동하지 않기

확인한 원본 파일은 `src/features/explorer/entry-delete-dialog.tsx`, `src/widgets/explorer/use-explorer-entry-crud.ts`, `src/entities/file/{file.query,file.ipc,workspace-resource-operations}.ts`, `src/entities/layout/tab-path-change.ts`, `crates/taide-runtime/src/file_actions.rs`, `crates/taide-layout/src/service.rs`입니다.

- 탐색기 EntryDeleteDialog는 locale title/description(name), 취소, destructive 삭제의 controlled AlertDialog입니다. onOpenChange(false)는 취소하며 Action의 원본 자동 닫힘·focus·Escape/외부 클릭 정책은 설치된 Radix source까지 확인한 뒤 재현해야 합니다. egui Modal::should_close는 backdrop click도 포함하므로 그대로 동일시하지 않습니다.
- 탐색기의 confirmDelete→useDeleteEntry는 plain fileDelete를 호출한 뒤 선택 프로젝트의 followDeletedPathInTabs/layout/cache와 parent tree를 갱신합니다. 이 GUI 경로에는 LSP prepare의 dirty 거절이 없습니다. Rust file_delete도 기존 Trash/self-write 경로이며 해당 LSP dirty guard가 없습니다. selected layout의 main/aux File 탭은 close_file_tabs_under로 닫습니다. 후처리 오류 일부는 TS에서 swallow하므로 성공 범위를 혼동하지 않습니다.
- 반면 workspace-resource-operations의 LSP 삭제는 경로를 포함하는 **모든** 열린 프로젝트를 준비하고 unsaved tab/model/mirror를 거절한 뒤 모든 해당 프로젝트의 탭을 갱신합니다. 이미 구현된 native `workspace_delete.rs`는 이 정책에 대응합니다. GUI 삭제에 그대로 연결하면 원본과 다른 dirty 거절·다른 프로젝트 탭 닫기가 생깁니다.
- explorer-open-and-context QA의 미완료 목록에 있는 “dirty 파일 거절”은 GUI 원본을 확정한 구현 계약이 아닙니다. 위 조사로 차이를 확인했으므로 재개 때 해당 문구와 실제 구현 범위를 함께 정정해야 합니다.

재개 후 `explorer_delete.rs`의 별도 GUI-confirmed pipeline을 선택·연결했습니다. 기존 LSP require-saved/all-project 정책은 유지합니다. selected layout의 File 탭만 닫고 survivor mirror는 최신 본문으로 보존해 기존 readonly missing-source 화면에 연결했습니다. TS의 다른 프로젝트 model/cache 회수 세부 경계는 완전히 해석하지 못했으며 이 보존 경로만으로 전체 수명 동등성을 완료 처리하지 않습니다. 상세·새 실제 성공은 explorer-delete QA와 survivor-draft-project-scope bug에 있습니다.

주의할 수명 경계는 `workspace_delete.rs`의 Prepare/Deleted GUI ack·captured identity/revision·owned guard, `workspace_activity.rs`, `persistence.rs`의 500ms mirror debounce/auto-save generation, `file_sync.rs`의 취소 epoch, `missing_draft.rs`, `application.rs`의 workspace_suspended·Delete reply 처리입니다. 현재 LSP prepare/commit_documents는 dirty를 거절합니다. editor store의 release_document는 dirty 회수를 거절하고 discard_document는 revision 일치와 attached view 없음이 필요합니다. 다른 프로젝트에서 살아 있는 view/doc를 무조건 버리거나 background 저장이 삭제 경로를 재생성하게 하면 안 됩니다. 원본 없는 파일의 읽기 전용 draft/Save As와 자동 저장 중지를 검토해야 하나 새 정책 구현 완료를 주장하지 않습니다.

1. 세션 경계 규칙에 따라 다중 에이전트 workflow 사용 여부를 **다시 한 번 질문**하고 답을 받은 뒤 도구 작업을 시작합니다. 이전 세션에서 사용자는 서브에이전트 미사용을 명시했지만 새 세션의 기본 선택으로 저장하지 않습니다.
