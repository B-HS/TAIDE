# 코드 수정 전구 클릭의 본문 선택 충돌

대상은 native/taide-native-ui/src/editor_surface.rs와 editor-code-actions.rs, editor-geometry.rs입니다. 실제 App 기본 화면에서 gutter 전구를 누르면 줄 번호 선택 처리가 먼저 실행돼 커서 12/12가 줄 선택 6/19로 변하고 수정 후보의 수명도 영향을 받았습니다. 첫 전체 App 검사에서 실제_app의_자동_전구는_공백_왕복과_목록_취소_후에도_다시_사용한다가 실패했습니다.

독립 UI 검사의 줄 번호를 켜면 현재_전구를_클릭하면_본문_편집_없이_같은_공급자_목록을_연다가 선택 0/0 대신 6/16으로 실패합니다. 실제 red 로그는 /private/tmp/taide-batch23-code-actions-pointer-red-actual.log이며 0통과/1실패·exit 101입니다. inspection 누락/필터 오입력의 0건 실행과 Fixture 필드의 컴파일 실패는 실행 성공 또는 버그 재현으로 세지 않습니다.

현재 줄 geometry와 전구 사각형 계산을 그리기와 hit-test가 함께 사용합니다. 실제 표시 가능한 전구의 눌림은 본문/줄 번호 선택과 접기 처리에서 제외하고 공급자의 기존 클릭 처리로 이어집니다. 이전 프레임 사각형을 사용하지 않아 스크롤·wrap·주입 텍스트 경계도 현재 layout으로 계산합니다. 기본 선택이나 접기 전반을 끄지 않습니다.

수정 후 UI 전체 24대상/461통과·exit 0이며 같은 UI 검사에서 줄 번호 없음/있음과 본문 안 전구의 세 사례를 확인했습니다. 실제 App 코드 수정 관련 23건·exit 0에서 전구 클릭의 선택/문서 보존·목록 열기·취소 뒤 재사용·편집/undo·정상 종료를 확인했습니다. 최초 App 전체 838통과/8실패·exit 101과 시간 초과 7건의 영향 재검사 성공을 구분하며 전체 실행이 성공했다고 바꾸어 기록하지 않습니다. 실제 OS 입력이나 사용자 데이터를 사용하지 않았습니다.
