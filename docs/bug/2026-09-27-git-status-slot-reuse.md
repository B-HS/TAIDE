# Git 상태 캐시 슬롯 재생성 경합

상태: 단위 테스트로 재현 후 수정 완료. 실제 GUI 경합 실기는 미검증입니다.

## 재현과 영향

`git_status`가 프로젝트 ID의 빈 슬롯에서 계산을 시작한 뒤 `GitStore::remove`가 슬롯을 회수합니다. 같은 ID를 다시 조회해 새 결과를 저장하고 이전 계산을 완료하면, 이전 구현은 새 상태를 옛 결과로 덮었습니다. 회수·재생성된 두 슬롯의 generation이 모두 0이었기 때문입니다.

`git_init`은 열린 프로젝트의 같은 ID에 대해 `remove`를 호출하므로, 닫힌 프로젝트 ID를 인위적으로 재사용해야만 생기는 경합은 아닙니다. 이 오류는 다음 무효화 또는 2초 TTL까지 잘못된 branch/status를 캐시에서 제공할 수 있습니다. 이번 테스트는 슬롯 동작만 검증하며 실제 Git 초기화·GUI 경합을 실행하지 않았습니다.

## 수정과 검증

`crates/taide-git/src/store.rs`의 슬롯마다 고유 `Arc<()>` identity를 부여합니다. 계산 영수증 `PendingStatus`는 identity와 generation을 보관하고, 완료 시 둘 다 현재 슬롯과 같아야 저장합니다. 이전 계산이 identity를 보유하는 동안 새 슬롯은 같은 allocation을 재사용할 수 없습니다. 기존 계산 중 무효화·TTL·슬롯 없는 완료 정책은 유지합니다.

회귀 테스트 `슬롯_회수_뒤_같은_id를_재조회해도_이전_계산은_새_슬롯을_덮지_않는다`는 원래 구현에서 assertion 실패(exit 101), 수정 뒤 store 검사 21건에 포함되어 통과했습니다. 테스트는 이전 main 계산·슬롯 회수·새 release 결과 저장·이전 계산 완료 순서를 고정하며 시간을 기다리지 않습니다.
