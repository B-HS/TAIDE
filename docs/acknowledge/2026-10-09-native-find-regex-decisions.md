# Native 찾기 정규식과 원본 버그 처리 방향

## 사용자 결정

2026-10-09 사용자 답변: "전체적으로 큼직한 기능들을 그냥 정확히 구현하는거지 버그마저 똑같이 구현할필요는 없어. 나머지는 추천대로".

대상은 `docs/research/2026-10-07-native-find-regex-dialect.md` 7절의 여섯 결정입니다. 후속 구현에서는 기존 TS의 화면·상태·상호작용과 큰 기능을 정확히 재현하되, 원본의 결함을 그대로 재현하는 것을 완료 조건으로 강제하지 않습니다. 새 기능·새 디자인을 추가하는 허가는 아닙니다.

1. JS 방언을 유지하며 `regress =0.12.0`을 원본 일치·성능 게이트로 평가합니다. 채택 완료나 게이트 통과를 뜻하지 않습니다. 탈락하면 근거를 보고하고 엔진 방향을 다시 결정합니다.
2. 새 의존성 1개를 앱 전용 경계에 정확한 버전으로 반입합니다. 기존 지시에 따라 `taide-native-syntax`에서 평가하며 editor/UI와 동결 remote-web의 의존 그래프·lockfile을 바꾸지 않습니다.
3. 줄·일치 사이에서 경과 시간을 확인해 중단하며 한 줄 안의 백트래킹 폭주는 TS와 같은 조건으로 수용합니다. 공개 budget API의 적용은 별도 버전 변경 판단입니다.
4. 대량 모두 바꾸기에서도 검색 옵션을 일관되게 유지합니다. 원본의 일치 19,999개 이상 경로에서 `m`을 강제로 추가하거나 단어 단위를 무시하는 결함은 재현 대상으로 삼지 않습니다. 경계 전후의 검색 대상·치환 결과가 같은 옵션 규칙을 따르는지 검증합니다.
5. 검색 패널과 찾기 위젯의 방언을 통일하지 않습니다.
6. 정규식 엔진의 영어 오류 문장을 표시합니다.

## 재개 범위와 남은 결정

이 합의는 정규식 선택과 원본 버그 처리 방향의 확정입니다. 이후 사용자가 "기존의 배치n까지 하고 멈추다는 지시는 무시한다"로 전체 재개를 확정했으며 `2026-10-09-native-full-resume.md`를 따릅니다. 나머지 HANDOFF 6절 결정(7자리 테마 색 값 등)은 임의 확정하지 않습니다. transpose의 U+FFFD 처리는 별도로 이미 확정된 결정을 유지합니다.

## 성능 기준과 채택

2026-10-09 사용자 답변: "100ms 합격 기준·1초 검색 상한 적용(추천)".

같은 30만 줄·20MiB 문서에서 일치 없는 전체 검색과 19,999개 수집을 각각 100ms 이내에 완료하면 채택합니다. 실제 찾기·치환은 줄·일치 사이에서 1초 상한을 확인합니다. 한 엔진 호출 내부의 백트래킹은 기존 결정대로 중단하지 못할 수 있습니다. 치환 계획이 시간 초과하면 일부 결과를 적용하지 않습니다.

엔진 기준값 3,800개, 찾기 모델 기준값 2,432개, 치환 패턴 기준값 2,624개를 검증했습니다. 이전 탐색은 문자열을 커서 앞에서 잘라 가짜 줄 끝·단어 경계를 만드는 원본 결함을 수정한 기준으로 검증하며 원본 결과도 fixture에 보존합니다. 1초 상한을 켠 최적화 빌드의 최종 관찰값은 전체 검색 32.256333ms·수집 4.6865ms이며 두 성능 기준을 충족했습니다. `regress =0.12.0`을 앱 전용 syntax 경계에 채택합니다. UI 위젯과 앱 연결의 완료를 뜻하지 않습니다. 명령·로그·제약은 `../quality-assurance/2026-10-09-native-batch8-find.md`에 기록합니다.
