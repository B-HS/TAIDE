# M7 단일 실기 검증 범위 결정

## 대상과 결정

사용자는 M7 GUI 전수 실기를 대표 핵심 흐름의 1회 검증으로 축소하고, 같은 성공 검사를 반복하지 않도록 결정했습니다. 이 결정은 현재 TS/Tauri 앱의 M7·Phase 0 기준선 작성에 적용합니다. 기존 212개 비테스트 `.tsx` 경로의 정적 inventory는 유지하되, 경로마다 GUI를 한 번씩 열어 전수 통과시켰다고 주장하지 않습니다.

- 자동 검증의 이미 성공한 동일 입력·환경 결과는 재사용합니다. 실패 수정 뒤에는 영향을 받은 경로만 다시 검증합니다.
- 남은 GUI 실기는 메인/보조 창, 대표 키보드·메뉴·dialog, 테마·로케일 표시, 접근성 상태를 한 통합 경로에서 각 한 번 확인합니다. 이미 확인한 파일·검색·설정·preview·terminal·LSP 정상 경로는 재측정하지 않습니다.
- M7 release 성능 기준선은 동일 기기·기준 fixture에서 지표별 유효 관찰값 한 건을 기록합니다. 이를 3회 중앙값이나 p95·p99로 부르지 않으며 단일 표본의 변동 위험을 명시합니다.
- 원격 HTTP/WebSocket, IDE WebSocket, 활성 자원 직접 Exit의 보안·수명 경계는 대표 GUI 화면만으로 대체하지 않습니다. 각각 실제 요청·응답 또는 종료를 한 번 확인해야 합니다.
- 이후 native 구현의 정량 성능 동등성·TS 화면 항목별 0누락 판정은 별도 gate입니다. 단일 M7 표본만으로 통계적 비악화나 구현 동등성을 선언하지 않습니다.
