# Rust 크레이트 분리 안 함 — 현행 유지 결정 (2026-08-28, 사용자 확정)

## 배경

사용자 질문: "crates 로 분리할 것들이 있나? 덩그러니 하나(taide-cli)만 빠져 있는데".
실측: 워크스페이스 = `src-tauri`(46.4k LOC) + `crates/taide-cli`(471 LOC, std+uuid 만 —
마커 파일·TCP 통신 런처라 의존 무공유가 정확한 설계). domain 24개 40.7k LOC 는 전부
tauri 무결합(0/122 파일 — 커스텀 dispatch 설계 덕), 풀 재컴파일 실측 16.7초.

## 결정

- **분리하지 않는다(현행 유지). 회귀 가드 테스트 추가도 하지 않는다.** (제시안 A=가드 추가
  권고였으나 사용자가 B "아무것도 하지 마" 확정)

## 이유

- 분리 3대 실익이 전부 부재: ① 컴파일 16.7초라 절감 여지 미미 ② 도메인 코드의 2번째
  소비자 없음(2회 이상 규칙의 크레이트 판 — 조기 분리) ③ tauri 무결합 경계는 이미 구조로
  지켜짐(0/122).
- 비용은 실재: 교차 도메인 참조 다수(ide 10·sync 10·layout 7)라 `taide-core`(error/events/
  ids/constants) 신설 + 122파일 임포트 churn.

## 기각된 대안

- 가드(grep) 테스트 추가(추천안이었음) / 분리 설계 문서만 작성 / 실제 분리 — 전부 기각.
- **재론 조건**: 도메인 코드의 두 번째 소비자(taide-cli 의 도메인 로직 사용, 헤드리스 서버
  단독 빌드 등)가 실제로 생길 때.
