# 배치 통합 검증에서 통합 테스트 회귀를 놓침

> 최종 갱신일: 2026-10-09 · 대응 커밋: `bf5175ca`
> 사용자 지적이 아니라 메인이 스스로 찾은 누락입니다. 같은 실수를 막기 위해 기록합니다.

## 무엇이 일어났나

배치 3(`562ef60c`)이 터미널 view 오류의 화면 도색을 TS 기준대로 없애고 경고 로그로 바꿨습니다. `native/taide-native-app/tests/terminal-host.rs`의 `headless_input_budget은_포화에서_선택을_유지하고_취소된_대기를_전송하지_않는다`는 화면에 그려진 "budget exceeded" 문구를 검사하고 있어 그때부터 항상 실패했습니다. 메인은 배치 3 통합 검증에서 이를 찾지 못한 채 커밋·푸시했고, 배치 4 검증에서야 발견해 `f0b3ae0a`로 고쳤습니다.

## 왜 놓쳤나

- 배치 3 통합 검증에서 메인이 앱 lib 테스트와 일부 통합 대상만 실행했습니다. 수정 단계의 작업자는 `terminal-host`를 자기 테스트 2건으로 필터해 실행했습니다.
- "변경 위험을 직접 덮는 최소 검증" 규칙을 좁게 적용했습니다. 터미널 표면의 표시 동작을 바꾸는 변경이면 그 표면을 쓰는 통합 테스트 묶음 전체가 직접 위험 범위였습니다.

## 어떻게 고치나

배치 통합 검증에서는 변경한 크레이트의 **전체 테스트 대상**을 `--no-fail-fast`로 1회 실행합니다(`docs/memory/2026-10-07-native-transition-operations.md` 4절). `--no-fail-fast`가 없으면 첫 실패 바이너리에서 멈춰 나머지 결과를 볼 수 없습니다.

## 언제 적용하나

- 여러 단계의 변경을 묶어 커밋하는 배치 통합 시점에 적용합니다. 단계별 작업자에게는 요구하지 않습니다(빌드 비용과 디스크).
- 사용자에게 보이는 동작을 없애거나 표시 채널을 바꾸는 변경은, 그 동작을 단언하는 테스트를 `rg`로 먼저 찾습니다.
