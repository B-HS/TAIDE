# compact 이후 subagent 모델 선택 누락 우려

## 사용자 지적

사용자는 재개 후 workflow 사용을 재확인하면서, subagent 모델은 DeepSeek V4.1 Flash `max` effort라고 다시 명시하고 선택이 유실되지 않도록 요청했습니다.

## 원인과 바로잡을 점

compact 후 이전 실행 선택을 자동 승계하지 않는 운영 계약에 따라 다시 물었으나, 질문에 앞서 진행 상태 문서에서 이전 모델 지정값을 확인 가능한 형태로 보존하지 않아 사용자가 유실을 우려했습니다. 이번 작업의 선택은 workflow 사용, 모든 subagent에 `ollama-cloud/deepseek-v4.1-flash#max`를 명시하는 것입니다. 모델 목록에서 이 ID와 `max` variant의 제공 여부를 확인했습니다.

## 적용 시점

이번 실행 작업의 모든 역할별 subagent 호출에서 해당 값을 직접 지정하고, 모델을 임의 대체하거나 설치 설정을 바꾸지 않습니다. 재개 작업에서는 `docs/PROCESS.md`에 기록된 요청을 먼저 확인한 뒤 상위 운영 계약에 따라 다시 선택을 확인합니다. 이는 향후 세션에서 사용자 선택을 자동으로 승계한다는 약속은 아닙니다.

## 현재 제약

이번 재개에서 역할별 모델 지정 CLI 호출은 실행 환경에서 `Permission denied: shell`로 거부됐습니다. 따라서 M2 구현을 호출하지 않았고, 권한이나 호출 경로가 허용되기 전에는 해당 지정 모델로 workflow를 실행했다고 보고하지 않습니다.

승격 후보: 없음. 사용자 선택은 현재 작업의 지정값이고, 재개 시 다시 확인해야 하는 상위 운영 계약을 장기 기본값으로 변경하지 않습니다.
