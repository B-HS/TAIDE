# 릴리스 버전 규칙 확인 전 버전 단정 금지

## 무엇을 지적받았나

사용자가 “버전에 `4`가 들어가면 안 된다는 지침이 있을 텐데 무시했네”라고 지적했습니다. 릴리스 작업을 시작하며 실제 배포 규칙을 읽기 전에 다음 패치 버전을 `v0.2.4`라고 먼저 안내했습니다.

## 왜 틀렸나

`docs/deployment.md` §2와 `docs/acknowledge/2026-08-28-release-tag-no-digit-4.md`에 릴리스 태그와 앱 버전에 숫자 `4`를 포함하지 않는 절대 규칙이 있습니다. 릴리스 버전은 일반적인 SemVer 증가를 추측할 대상이 아니라 저장소 배포 규칙을 먼저 확인해 결정해야 합니다.

## 어떻게 고치나

현재 릴리스 버전을 `v0.2.5`로 정정합니다. 앞으로 태그·버전 변경 요청에서는 첫 안내 전에 배포 정본의 버전 금지·건너뛰기 규칙과 기존 최신 태그를 함께 확인합니다.

## 언제 적용하나

이 저장소에서 버전 증가, 태그 생성, 릴리스 또는 draft 생성을 수행할 때 적용합니다.

## 승격 후보

없습니다. 이미 `docs/deployment.md` §2와 acknowledge 정본에 절대 규칙으로 명시되어 있으므로 새 규칙으로 승격할 필요가 없습니다.
