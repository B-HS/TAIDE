# 기능률 반복 보고와 배치 끝점 교정

## 사용자 지적

> 너 자꾸 "기능 대응표 48.6%" 라고 말하는데 정확히 판단하고 그리고 너가 무한루프에 빠지지않았는지도 제대로 체크해 그리고 배치는 대체 몇까지하는거야

## 문제

배치 21 기능표의 요구사항 행 비율을 배치 22에서도 고정적으로 반복 보고했습니다. 자동완성/스니펫 실제 소비자가 생겼는데 표의 missing/unwired 분류는 갱신되지 않았으며 옛 markup 경로 때문에 정합성 검사도 실패했습니다. 전체 마이그레이션의 진척을 설명하는 데 서로 다른 크기의 요구사항 행 비율은 부족했습니다. 마지막 배치 번호를 정하지 않고 세부 기능별로 배치를 추가해 종료 범위도 설명하지 못했습니다.

## 교정과 적용

분모와 상태를 직접 재집계하고 현재 동작·최근 commit diff·검증 로그·프로세스를 대조합니다. 완료한 동작과 현재 연결/검증 중인 범위, 남은 전체 게이트를 보고하며 정확한 전체 진척률이나 소요시간 근거가 없으면 미산정이라고 씁니다. 같은 입력·코드·환경의 성공 검사는 재사용하고 단순 반복을 진척으로 세지 않습니다.

배치 22 자동완성·스니펫 두 행은 partial로 갱신하고 전체 게이트 전에는 complete로 올리지 않습니다. 남은 302행과 전체 통합·전환·제거 게이트는 [배치 22~33 계획](../quality-assurance/2026-10-10-native-remaining-batch-plan.md)에 고정하며 세부 수정은 해당 배치 안에서 처리합니다. 현재 목표에 대한 다음 진척 보고부터 적용합니다. 메인의 계획을 사용자가 확정한 결정으로 기록하지 않습니다.

자세한 점검 근거는 [진척 감사](../quality-assurance/2026-10-10-native-progress-audit.md)에 있습니다. 이번 기록은 native 전환 작업의 보고·범위 교정이며 별도 전역 규칙 승격은 하지 않습니다.
