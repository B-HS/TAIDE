# 재시도 대기 타이머는 1분 단위로 (2026-08-14)

## 무엇을 지적받았나

API 과부하(529)로 워크플로가 실패하자 5분 → 15분(다음은 30분) 식으로 대기 타이머를 늘려 걸었다.
사용자: "타이머를 15분 10분 이딴식으로 걸지마. 걸어도 1분 단위로 걸어."

## 왜 틀렸나

일시적 과부하는 수십 초~수 분 안에 풀리는 경우가 대부분인데, 긴 지수 백오프는 복구 후에도
남은 대기 시간만큼 세션을 놀린다. 사용자는 세션이 붙어 있는 동안 최대한 빨리 재개되기를
원하며, 재시도 비용(호출 1회)은 대기 비용(수십 분 유휴)보다 훨씬 싸다.

## 어떻게 고치나

- 외부 장애(529 등) 재시도 대기는 **60초 고정 간격**으로 건다. 지수 백오프로 늘리지 않는다.
- 실패가 장기간(예: 30분 이상) 지속되어 반복 자체가 무의미해지면 간격을 늘리는 대신
  **사용자에게 보고하고 지시를 받는다.**

## 언제 적용하나

이 프로젝트(TAIDE)에서 백그라운드 재시도·폴링 대기를 걸 때 항상. 다른 프로젝트에서도
사용자가 세션에 상주하는 인터랙티브 작업이면 동일하게 적용한다.
