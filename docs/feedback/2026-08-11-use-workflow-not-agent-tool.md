# 구현 위임을 워크플로가 아닌 단일 Agent 도구로 보낸 위반 (2026-08-11)

## 무엇을 지적받았나

W1 메인 2차에서 발견한 잔여 테마 결함 수정을 Workflow 가 아니라 general-purpose 단일 에이전트로
위임했다. 사용자: "내가 언제 general purpose 를 쓰라 했지? 분명 handoff 및 세션 시작에 workflow
방식을 표시해놨을텐데."

## 왜 틀렸나

- HANDOFF §5.1 과 acknowledge(2026-08-07)에 "판단/리서치/구현/디버그는 workflow 로 진행한다"가
  명시돼 있다. "작으니까 예외"는 합의된 예외 목록(fable 지정 디버그·취약한 네트워크 다운로드·
  2차 검토의 소규모 직접 수정)에 없다 — 위임하는 순간 워크플로 규칙이 적용된다.
- Agent 도구는 effort 를 지정할 수 없어 "구현 = sonnet + high" 역할 계약도 함께 어겨진다.
- 워크플로를 쓰지 않으면 검토(렌즈→적대적 검증) 단계가 함께 생략되기 쉽다.

## 어떻게 고치나

- 서브에이전트 위임은 규모와 무관하게 **Workflow 도구로** 한다. 단일 작업이어도 agent() 1개짜리
  워크플로로 실행하면 model/effort 지정과 단계 구조가 유지된다.
- 메인이 직접 해도 되는 것은 합의된 예외 3종뿐이다. 그 외는 전부 워크플로.

## 언제 적용하나

- 이 레포에서 서브에이전트에게 일을 맡기는 모든 경우. 항상.
